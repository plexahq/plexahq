How Plexa works.

Plexa is an MCP gateway for on-chain networks. You add one URL to your AI client, and from then on it can read any wallet, explain any contract, dry-run any transaction and follow any LayerZero message, all in plain conversation. This page walks through what happens between your question and the answer.

MCP in one paragraph

The Model Context Protocol is an open standard for connecting AI assistants to tools. A client that supports it (Claude, Claude Code, ChatGPT, Cursor, VS Code) can be pointed at an MCP server and will see that server's tools, with a description of what each one does and what it needs. When you ask something, the assistant decides which tool fits, calls it, and uses the result in its reply. Plexa is an MCP server built for blockchains.

01 · The path of a request

From a sentence to the chain and back.

  1. 01You ask

    In plain words, in the client you already use. "Is this approval safe?" "Where is my bridge transfer?"

    Your AI client
  2. 02A tool is picked

    Your assistant sees Plexa's sixteen tools and their inputs, chooses the ones that fit and fills in the details.

    MCP tool call
  3. 03Plexa reads live sources

    RPC nodes for state, LayerZero Scan and the official registry for cross-chain messages, Sourcify for verified code.

    Read-only
  4. 04The answer is checked

    Calls are decoded, proxies followed, transactions simulated, known drainer patterns flagged.

    Simulate · decode
  5. 05You decide

    Your assistant explains the result in plain language. If anything ever needs a signature, it is yours to give.

    Your wallet

03 · Simulation

Simulated first. Then it's your call.

Before you sign anything, Plexa runs the exact transaction against live chain state without broadcasting it. It reports whether it would succeed, what it would cost and what it really does, decoded from verified source. Then it looks for the traps people sign every day:

  • Unlimited token approvals
  • Approvals to plain wallets instead of contracts
  • Tokens sent to the token contract itself
  • Unverified contracts and unverified EIP-7702 delegates
  • Transfers that would revert, caught before gas is spent
